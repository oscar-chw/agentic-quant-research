# Chapter 20, second reading

An auditor who did not write `docs/claims/ch20.md` re-read every line of all thirteen heading spans, listed the claims,
compared them with the items, and opened every test a `done` item names (plan/book-v2.md node 18). The counting
convention is the one stated in `audit/ch18.md`.

This chapter is hardware-agnostic by design, so most of it is implementable here and the items implement it: both
partitions, the molecule dispatch, the serial debugging path, asynchronous calls with progress, on-the-fly reduction and
the column-block principal components. The tests are structural and they bite -- the nested partition is compared with
the linear one on the same triangle, the parallel result is compared with the single-process one, and the reduced output
with the collected one. Two defects were found. Every one of the chapter's fourteen snippets was implemented and
evaluated by some item, and named by none, which is what the element rule exists to catch. And the one claim in the
chapter that is about elapsed time rather than structure, that more batches than cores keep every core busy, was
attached to a test that asserted only that the molecules got smaller.

The chapter's hardware judgements were re-checked against docs/hardware.md: 12 cores of which research uses 4, 0.8 GB
per worker against 32 GB, the event build's 1.18 M rows in about 40 minutes. Each not-applicable row cites one of those
numbers and none of the arithmetic was wrong; I20.54's note cited the core count in a form ("12-core") that the
checker's quantity rule does not read, and now cites it plainly.
