# Chapter 21, second reading

An auditor who did not write `docs/claims/ch21.md` re-read every line of all twelve heading spans, listed the claims,
compared them with the items, opened every test a `done` item names, and re-ran the hardware arithmetic the chapter's
not-applicable rows rest on (plan/book-v2.md node 18). The counting convention is the one stated in `audit/ch18.md`.

The library itself is in good order: the pigeonhole count, the full-investment constraint, the square-root cost, the
Sharpe ratio, the walk of the search space by index and the exhaustive search against an independent enumeration
written a second time inside the test. Four defects were found.

1. **Eight items named two tests that do not exist.** `test_every_feasible_weight_vector_is_fully_invested` and
   `test_the_search_still_answers_with_a_singular_covariance` were renamed in `tests/test_afml_trajectory.py` and the
   item file was never updated, so the chapter could not pass its own gate. Both names corrected.
2. **The throughput was assumed, not measured.** The file claimed 130,000 evaluations a second per core and "so about
   520,000" on 4 workers. Measured: 119,000 on one core and 313,000 on four, a 2.6-fold speed-up, not 4-fold. The
   number is now a row of docs/hardware.md.
3. **The headline arithmetic was right in form and wrong in magnitude.** 10 units across 5 assets is 32,032 weight
   vectors and 32,032^4 = 1.053e18 trajectories: that part checks out exactly. At the measured rate it is 9.3e8 hours,
   about 107,000 years, not the 64,000 the assumed rate gave.
4. **The "largest case that fits" was counted off the wrong set.** It read 1,344 vectors for 6 units across 4 assets,
   the nominal count, while the search walks the 608 distinct ones (I21.33's own point). Recomputed on the set the code
   searches, the largest case inside the hours-not-days ceiling is 8 units across 4 assets over 3 horizons: 1,408
   vectors, 2.79e9 trajectories, about 2.5 hours.

All four are closed, and the arithmetic is now a test that can fail:
`test_the_hours_this_machine_would_need_are_the_count_over_the_measured_rate` asserts the counts, the measured rate's
sub-linear scaling, and each conclusion drawn from them.
